# Public-data evaluation (Phase 09, partial)

This is a development runner, not a release-quality leaderboard. It uses pinned public native schemas, one explicit local answering model per run, matched memory/answer limits, and visible failures. It never downloads models or falls back to an extractive/mock answer during a run. Asset preparation is a separate explicit command.

Current checkpoint (2026-10-04 07:41 UTC): the owner selected local Qwen 2B/4B/8B answering and Ollama Cloud independent judging/larger-model references. The frozen full-S 2B campaign reached 126/4,500 rows and continues. Cloud Gemma4 31B development reference and separate GPT-OSS 120B grading completed 27 rows; human calibration is pending. These are development diagnostics, not full public superiority evidence. See the current [handoff](../../docs/implementation/handoffs/09.md); older numbers below are historical.

Optional `--encoder-backend onnx --embedding-path PINNED_LOCAL_ASSETS` keeps inference offline and fingerprints all assets/backend dependencies. `--corpus-cache DIRECTORY` reuses only checksum-bound native content/indexes; question/gold/model answers never enter cache identity/content. Each question restores its own mutable database. Physical build/restore costs are reported separately from original inherited build costs.

Grading accepts `--judge-provider cloud --judge-model gpt-oss:120b --judge-digest d98fe6ba01e6 --judge-output-tokens 512`; credentials come from the environment or protected Windows storage, never manifests. Provider revisions are short catalog tags, not full weight digests. Cloud structured outputs are unsupported, so native JSON-schema management models need independent compatibility qualification. `scripts/resume_grading.py` restores the verified grader snapshot and preserves completed failures. Frozen reviews require human labels/rationales; validation reports agreement/disagreements/missing grades without pretending to supply human judgment.

The destination must be new unless `--resume` is explicit. Raw rows append after each question/profile. Resume validates manifest/split checksums, source and SDK hashes, and model/config inputs; completed rows, including failures, are preserved and skipped. The resume helper executes the verified source snapshot, but a changed SDK still requires a new experiment. Duplicate, unknown or malformed rows fail visibly. `--selection evaluation` runs every frozen holdout question; `--selection development` runs its full development partition. Default `--selection smoke` is a small development qualification. Select full haystacks with `--longmemeval-variant s` or `m`; the default remains explicitly labelled `oracle`. `--dataset` can select both, locomo or longmemeval without changing frozen membership. `--max-new-cases` bounds one execution, never the expected denominator; the runner emits incomplete coverage rather than a full summary until all rows exist. Missing judges remain unknown with full-denominator bounds.

`pins.json` identifies source commits, download URLs, SHA-256 checksums, licenses and official scoring code. LoCoMo10 retains native speakers, session dates, dialog IDs, participant/user observations and released image captions; images are not downloaded. Oracle and full S/M LongMemEval distractor haystacks are prepared and verified (500 QA per variant). The streaming reader avoids loading the multi-gigabyte M corpus at once. Native roles, session IDs/date literals, question dates and answer-bearing turn flags are preserved without a guessed timezone. Downloads resume only verified HTTP range responses and validate the entire checksum before promotion.

Native answers/evidence never enter retrieval or generation except the labelled oracle profile. Session IDs and duplicate session content connect question groups before splitting. Smoke selects the first eligible QA per development cluster without consulting performance. Full S/M freezes each contain 2,486 QA: 365 development and 2,121 evaluation, with all 500 LongMemEval questions in one connected evaluation cluster. Tuning trials: zero. Holdout execution is partial: full-S LongMemEval has 18/4,500 profile rows, not a completed accuracy result. SDK repairs after that run intentionally prevent extending it with a different SDK; use a new output directory.

Profiles use one common timestamped reference rendering and prompt: stateless, rolling, full-context, lexical BM25, real mean-pooled dense, RRF hybrid, genuine NSN ContextPacker lexical/semantic candidates, and oracle. NSN profiles are raw-event retrieval with facts, graph, sleep and procedures disabled. Neutral ingestion never parses gold annotations as facts. NSN candidate packing is followed by the same common whole-turn UTF-8 byte budget as other retrieval profiles. This evaluates candidate retrieval under a matched budget, not the complete wrapped chat formatting lifecycle. Full-context deliberately has no retrieval cap, but cannot silently exceed the answering model window: overflow is a recorded failure.

Current limits: 512 reference UTF-8 bytes, context 2048 tokens, output 32 tokens, seed 42, temperature 0, thinking disabled. The prompt-window check uses a conservative UTF-8 byte upper bound plus 256 chat-template tokens; it is not an exact tokenizer measurement. Actual Ollama input/output token counts, stop reasons, model digest/quantization/template, load/prefill/decode durations and requests/answers are recorded. Encoder weights/configuration checksums identify prepared MiniLM assets. No neural assets are loaded by the default SDK.

LoCoMo answer scoring executes the checksum-pinned upstream normalization, Porter stemming, multi-answer F1 and category conventions. LongMemEval executes its upstream judge prompt, but `--local-judge` uses the answering model as a diagnostic self-judge, not the official reference judge. Without that flag, LongMemEval answers remain unscored for later independent judging. Historical self-judge scores remain excluded from accuracy. Cloud grading is now explicitly configured for evaluation, with human/reference validation pending.

Intervals use paired conversation-cluster bootstrap, seed 42, 2000 draws, and are suppressed for unknown grades or fewer than two independent clusters. Two clusters still provide weak generalization evidence. Comparisons are exploratory and unadjusted. Runner RSS is sampled client memory excluding Ollama; separate installed minimal/semantic process-tree profiles live in Phase 10 artifacts. Extraction/consolidation calls are zero in these disabled profiles. Stale-answer/conflict metrics need validated annotations; QA F1 is not agent task success.
