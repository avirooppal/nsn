# Phase 07 handoff — Explicit recoverable consolidation

Date: 2026-10-03. Status: complete and verified; summary retrieval/enrichment remain opt-in. Phase 08 is not started.

## Outcome and defaults

`nsn.sleep()` or `runtime.sleep()` explicitly organizes changed memory into source-linked extractive records. Nothing schedules sleep, starts a daemon, or calls a model automatically. Original events and fact history are preserved. Summary retrieval is **off by default**, because the matched development ablation showed no gain. Opt in using `retrieve_pack(..., use_summaries=True)` or a supported wrapped call with that option.

This implements the plan's separation of foreground retrieval from bounded background consolidation. It does not reproduce biological sleep, Zep's full temporal graph pipeline, or A-MEM's model-driven memory evolution; those references motivate separation and provenance, not a performance claim.

## Prerequisite repairs

- Relationship extraction retries now reuse existing same-scope relation/support records and unresolved records. Default relation validity starts at its source event's time. Extraction checks that source text is unchanged under the writer lock; source updates invalidate existing support.
- Vector rebuild preserves vectors indexed after the rebuild began. A test inserts new memory while older sources are encoding and verifies the new vector survives replacement.
- Graph/summary retrieval controls are intercepted by adapters rather than forwarded to strict model providers. Wrap-level defaults and per-call overrides work through synchronous and asynchronous callable paths and the OpenAI proxy.
- An old performance assertion conflated whole-database metadata with vector payload. The benchmark now reports complete database bytes per item and separately verifies exact 384-dimensional float32 payload (1,536 bytes/vector). Schema/lineage storage growth is reported, not hidden by changing a threshold.

## API

```python
import nsn
memory = nsn.init("./agent-memory")
model = nsn.wrap(your_model)
report = nsn.sleep(max_jobs=8, max_sources=4, time_budget_ms=1000)

fact = memory.record_fact(subject="user", predicate="language", value="English")
memory.pin(fact.id)
report = memory.sleep(importance_decay=0.95)

# Inspection / explicit experiment, not the default retrieval path:
pack = memory.retrieve_pack("user language", use_summaries=True)
```

Optional graph connection requires `graph=True` and `sleep(connect=True)`. It uses the Phase 06 conservative grammar; it does not guess relations from co-occurrence.

`sleep` limits: default 8 jobs, 4 sources/job, 1,000 ms soft deadline, 4,096 summary bytes; configurable maxima are 100 jobs, 32 sources/job, 60,000 ms, 65,536 summary bytes. Neighborhoods are same-session events or same-subject facts within one namespace. Individual events with no session share their namespace's default neighborhood.

The report contains enqueued/processed/failed/skipped counts, summary IDs, pending and terminal-failed consolidation jobs, pending vector jobs, failure reasons, elapsed time, enrich/connect/summarize/validate/compact counters, model command attempts, input/output bytes, and maximum sampled command-tree RSS.

Importance is stored separately from fact truth/status/retention. Explicit decay applies once per successfully consolidated source revision, only to unpinned sources. It never deletes or demotes truth. Pinning is scoped; it suppresses importance decay, not an explicit user deletion. There is no wall-clock decay daemon or automatic retention policy.

Scheduling is opt-in: a user's scheduler can invoke this bounded public `sleep` command periodically. This phase creates no schedule itself.

## Durable pipeline and consistency

- Migration 6 creates a persistent source revision/processed/queued ledger. Insert/update/delete triggers track changes. A one-time migration seeds existing original sources; subsequent sleep runs use a partial dirty-source index, not pairwise comparison or namespace-wide content scans.
- Deterministic job/output IDs incorporate scope, source IDs/revisions, and settings. Queue insertion and queued-revision advancement share one transaction. Expired leases resume; each invocation uses a unique lease identity, including when a caller supplies a worker prefix.
- Work happens outside the writer lock. Final commit revalidates lease ownership and every source/dependency under `BEGIN IMMEDIATE`, then commits summary event, FTS entry, support lineage, optional unconfirmed proposals, revision checkpoint, importance, vector outbox intent, and job completion together.
- Whole source text is copied, with source ID/revision/time/identity. Facts retain raw exact values, units, qualifiers, disputed status, conflict group, and half-open validity intervals. Sources over the configured bound fail explicitly rather than silently truncating identifiers or numbers.
- Current summaries are excluded from every as-of query, even with `use_summaries=True`. Summary vectors are filtered before top-k selection, so disabling them does not consume original-evidence candidate slots. Original fact history supplies historical evidence.
- Event summaries depend on any linked active facts as well as the original event. Correction, supersession, deletion, or support changes invalidate dependent summaries immediately. FTS copies are deleted and vectors tombstoned; other runtimes' caches observe the vector-change counter. Source updates also invalidate enrichment proposals. Original events remain unless explicitly deleted.
- A dedicated cleanup queue bounds lineage compaction. No memory content is deleted based on low importance or trust.
- Semantic summary indexing uses ordinary `vector_index` outbox jobs. Explicit `runtime.process_index_jobs()` processes them; `sleep` reports pending index jobs rather than hiding model work or claiming the index is already flushed.
- Retry limit is 3. One failed attempt per invocation prevents consuming all retries immediately. Terminal failed jobs remain inspectable through `storage.list_jobs(status='failed')`; a source change creates a new revision/job. Queued jobs retain their original settings, including any previously configured enrichment command; a subsequent explicit sleep can resume that work. Failed groups do not permanently block new neighborhoods. No automatic retry reset is provided.

## Optional local enrichment

`enrichment_command` is an explicit argument list, run without a shell. No stored source text becomes executable command text. The backend receives JSON records and must emit exactly `{"proposals":[...]}`. Each proposal has source_type/source_id, subject, predicate, value, span_start/span_end. Value must equal an exact same-scope source span; schema violations reject the job. Proposals remain `unconfirmed`, are never inserted as facts/relations, and are never retrieved into model context.

Limits: 8 proposals, input/output byte caps (8,192 default, 65,536 maximum), 2 seconds per command by default (10 maximum), and 512 MiB sampled process-tree RSS by default (4,096 maximum). Timeout/output/RSS excess terminates the command and observed descendants. The command must run its model in its foreground process tree: external model servers or detached daemons are outside these accounting guarantees and are not supported by the provided worker.

Install optional extras only when using enrichment: `pip install 'nsn[enrichment,semantic]'`. The provided CPU-only worker uses existing local Hugging Face causal-model assets, `local_files_only=True`, `trust_remote_code=False`, capped output tokens and CPU threads:

```python
import sys
memory.sleep(
    enrichment_command=[sys.executable, "-m", "neurosleepnet.sleep.local_worker",
                        "--model-dir", "/absolute/path/to/local/slm"],
    enrichment_timeout_seconds=10, time_budget_ms=15000,
    max_model_rss_mb=2048,
)
```

The worker is packaged with NSN; model weights are not bundled. No model was downloaded or real generative enrichment quality claimed. Protocol, rejection, timeout, input/output, memory caps, and proposal invalidation were verified with local Python subprocess backends. RSS/output monitoring is sampled every 5 ms; these and SQLite deadlines are bounded operational controls, not hard real-time/instantaneous allocation guarantees.

## Development ablation and limitations

Dataset SHA-256: `11b6c935daaa2aac302df572ef41269d24b8d5a5c7a39a6bed10c6787d33272d`. Four frozen queries, nine original events, matched scopes/session/query/budget/distractors (none), BM25 candidate limit 1 and 512 tokens. Twenty foreground query repetitions per case. Complete-value scoring requires all gold exact values; source coverage counts all source IDs. No generated-answer metric or competitor comparison.

| Measurement | Sleep off | Sleep on |
| --- | --- | --- |
| Complete exact-value queries | 25% | 25% |
| Mean gold-source coverage | 54.17% | 54.17% |
| Mean foreground query p50 | 3.298 ms | 3.278 ms |
| Explicit sleep work | 0.051 ms | 130.121 ms |
| Maximum sampled RSS | 24.76 MiB | 25.25 MiB |
| Maximum sampled RSS increase | 0.105 MiB | 0.168 MiB |
| Checkpointed database size | 319488 bytes | 327680 bytes |
| Original events retained | 9 | 9 |
| Extractive summaries | 0 | 4 |
| Model commands invoked | 0 | 0 |

There was no measured quality gain. BM25 preferred shorter raw records over longer extractive bundles at this candidate limit. We did not add a ranking boost to manufacture a gain. Summary retrieval and enrichment remain off by default. This is a correctness/operational milestone, not a claim of beneficial semantic compression. A larger public evaluation and real SLM answer comparison remain Phase 09.

Original events are preserved (9/9). Extractive summaries increase storage; they are not deduplication or abstractive compression. Importance currently records a separate signal; it does not affect retrieval ranking. Source revision and cleanup metadata are overhead even before explicit sleep. A 1k semantic fixture's full database footprint increased to approximately 3,035 amortized bytes/item during validation, while raw vector payload remains 1,536 bytes/vector. RSS figures are sampled process measurements, not OS high-water marks.
