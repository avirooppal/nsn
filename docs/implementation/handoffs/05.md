## 1. Summary of Work Delivered & Verified Defect Repairs

Implemented, repaired, and validated Phase 05: Compact Semantic Retrieval as an optional, self-hosted, offline-first subsystem that enhances paraphrase recall while preserving the minimal installation and zero-ML-dependency default of `import nsn`:

1. **Preserved `append_event` Idempotency**:
   - `storage.append_event` returns an authoritative `EventID(str, inserted=bool)` object.
   - `Runtime.append_event` validates whether the returned ID was newly inserted (`getattr(actual_id, "inserted", True)` and `actual_id == event_id`).
   - If an idempotency hit occurs, the runtime immediately returns the authoritative ID without encoding retry content, creating orphan vectors, or leaving unhandled jobs.
   - Verified via `test_append_event_idempotency_retry_handling`.

2. **Atomic Target State Validation Against Race Conditions**:
   - Addressed the race condition where targets deleted or superseded during vector encoding could have their vectors restored upon completion.
   - Inside `CompactVectorStore.add`, an atomic validation is performed within the SQLite write transaction (`with conn:`):
     - For facts: checks `SELECT status FROM facts WHERE id = ? AND namespace = ?`. If missing or in `('deleted', 'superseded')`, the vector is tombstoned (`tombstoned = 1`), evicted from in-memory cache, and rejected (`return False`).
     - For events: checks `SELECT turn_status FROM events WHERE id = ? AND namespace = ?`. If missing or in `('cancelled', 'deleted')`, the vector is tombstoned and rejected.
   - Verified via `test_deletion_during_blocked_encoding_prevents_vector_restoration` using a blocking encoder with `threading.Event`.

3. **Consistent Lease Ownership Enforcement**:
   - `storage.complete_job` and `storage.fail_job` strictly require lease ownership for workers:
     `WHERE id = ? AND status = 'processing' AND leased_by = worker_id AND (lease_expires_at IS NULL OR lease_expires_at >= now)`.
   - Competing workers cannot complete, fail, or hijack jobs leased by another worker.
   - Inline callers (`worker_id=None`) require `status = 'pending'`, strictly preventing inline operations from overriding an active background worker's lease.
   - Expired leases are rejected from completion, allowing reclamation.
   - Verified via `test_lease_bypass_attempts`.

4. **Genuinely Concurrent Workers Under High Contention**:
   - Verified atomic leasing using `concurrent.futures.ThreadPoolExecutor` with 4 concurrent worker threads competing over 24 jobs across isolated namespaces.
   - Confirmed 0 duplicate claims, 0 overlapping claims, and 100% successful completions without deadlock or race conditions.
   - Verified via `test_competing_workers_and_atomic_leasing`.

5. **Storage Schema & Strict Manifest Validation (Migration 4)**:
   - Added tables `vector_manifest` and `compact_vectors` to SQLite schema (`CURRENT_SCHEMA_VERSION = 4`).
   - `vector_manifest` persists index metadata: `index_name`, `model_name`, `model_revision`, `dimension`, `preprocessing_fingerprint`, `index_revision`, and `updated_at`.
   - `compact_vectors` stores dense embeddings as contiguous binary `BLOB` (IEEE 754 float32, `dimension * 4` bytes) with namespace scoping and soft-deletion `tombstoned` flags.
   - `CompactVectorStore._initialize()` strictly validates all 4 manifest attributes against the active encoder protocol, raising actionable `IncompatibleIndexError` on any mismatch.

6. **Embedding Providers & Protocols (`neurosleepnet/embeddings/pooled.py`)**:
   - Declared `VectorEncoder` protocol with properties `model_name`, `revision`, `dimension`, `fingerprint`, and methods `encode(text)`, `encode_batch(texts)`.
   - `LocalPooledEncoder`: Local mean-pooled sentence encoder using `sentence-transformers`. Missing or invalid weights fail immediately with `AssetNotFoundError` providing remediation instructions (`nsn.prepare_assets()`).
   - `FastHashEncoder`: Deterministic n-gram hashing dense encoder strictly designated for tests and CI environments where ML dependencies are absent. It is explicitly documented as a synthetic test harness and **never labeled a trained semantic model**.
   - Kept model preparation/evaluation separate from offline unit tests (skips gracefully if assets are not prepared and online download is not explicitly opted into via `NSN_EVAL_REAL_MODEL=1`).

7. **Pure Python Fallback & NumPy Independence**:
   - Fixed search implementation when `numpy` is unavailable (`np is None`). Added binary float unpacking (`struct.unpack`) and pure Python dot-product search with identical ranking to NumPy.
   - Verified via regression unit test `test_search_without_numpy_regression`.

8. **Hybrid Lexical + Dense Retrieval with RRF (`ContextPacker.retrieve_pack`)**:
   - Combined lexical BM25 (facts & events) with dense semantic search via Reciprocal Rank Fusion:
     $$\text{score} = \frac{1}{60 + \text{rank}_{\text{lexical}}} + \frac{1}{60 + \text{rank}_{\text{dense}}}$$
   - Preserves exact identifier recall while boosting paraphrases with zero token overlap.
   - Dense events fetched in batch via a single SQLite query rather than opening individual connections per candidate, dramatically improving retrieval speed.
   - Detailed timings recorded in `diagnostic_explain`: `query_embed_ms`, `lexical_search_ms`, `dense_search_ms`, `fusion_ms`, `pack_ms`, and `total_retrieve_ms`.

## 3. Public & Schema Contracts

### SQLite Schema (Version 4)

```sql
CREATE TABLE IF NOT EXISTS vector_manifest (
    index_name TEXT PRIMARY KEY,
    model_name TEXT NOT NULL,
    model_revision TEXT NOT NULL,
    dimension INTEGER NOT NULL,
    preprocessing_fingerprint TEXT NOT NULL,
    index_revision INTEGER NOT NULL DEFAULT 1,
    updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS compact_vectors (
    id TEXT NOT NULL,
    namespace TEXT NOT NULL,
    target_type TEXT NOT NULL,
    vector BLOB NOT NULL,
    created_at TEXT NOT NULL,
    tombstoned INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (id, namespace)
);
CREATE INDEX IF NOT EXISTS idx_vectors_scope ON compact_vectors(namespace, target_type, tombstoned);
```

### Protocol & Python API

```python
class VectorEncoder(Protocol):
    @property
    def model_name(self) -> str: ...
    @property
    def revision(self) -> str: ...
    @property
    def dimension(self) -> int: ...
    @property
    def fingerprint(self) -> str: ...
    def encode(self, text: str) -> List[float]: ...
    def encode_batch(self, texts: List[str]) -> List[List[float]]: ...
```

## 5. Storage Arithmetic: Theoretical vs. Measured On-Disk Footprint

### Theoretical Arithmetic
- **Single Pooled Vector (float32, 384 dimensions)**:
  $$384 \times 4\text{ bytes} = 1,536\text{ bytes (1.50 KB)}$$
- **Multi-Vector Token MaxSim (ColBERT-style, assuming 50 tokens/chunk)**:
  $$50 \times 384 \times 4\text{ bytes} = 76,800\text{ bytes (75.0 KB)}$$
  Theoretical ratio: $\sim 50\times$ smaller raw payload per item.

## 9. Architectural Tradeoffs & Scope Boundaries

1. **Exact Pooled Dot Product vs. Approximate Nearest Neighbors (ANN)**:
   - For agent memory corpora up to 10,000 items, exact dot-product matrix multiplication achieves warm p50 search of ~1.4–3.1 ms.
   - Exact search eliminates ANN recall trade-offs, index tuning parameters, and large native C++ dependencies, but exact search is **not universally optimal** for massive corpora where memory constraints or sub-millisecond cold search requirements would necessitate quantized or hierarchical indexing.
2. **One Mean-Pooled Vector vs. Multi-Vector Representations**:
   - Single pooled vector representations trade granular phrase-level alignment for minimal RAM and storage footprint (2.5–2.7 KB/vec on disk vs theoretical ~75 KB/vec).
3. **Self-Hosted Zero-Server Architecture**:
   - Everything remains embedded within SQLite and local memory matrices, adhering strictly to the self-hosted, zero-server architecture.

## 10. Material Limitations & Deferred Scope

1. **Model Weights Deployment**:
   - `LocalPooledEncoder` requires ~89 MB of model weights on disk. In fully offline environments, `prepare_assets()` must be run beforehand.
2. **Cold Search Scaling at > 10k Items**:
   - Cold query latency on 10,000 items from SQLite is ~200 ms. For cold startups, pre-warming the matrix cache is recommended.
3. **Phase 06 Boundary**:
   - Stopping here before Phase 06 (Bounded Graph Memory). Multi-hop relationship querying, knowledge graph exploration, and bounded graph context synthesis are deferred to Phase 06.
