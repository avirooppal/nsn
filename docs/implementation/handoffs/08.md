## Delivered behavior

- Migration 7 adds scoped `procedures` and `procedure_traces`. Procedures represent title, prerequisites, ordered text steps, environment key/value constraints, required tools, status and creation time. Traces record source event IDs, outcome, evidence channel and time.
- Creating a procedure makes it unverified. An assistant claim, including a claim of success, never confirms it. `record_outcome(..., evidence='observed')` is a trusted host operation requiring a user/tool source event. `explicit_confirmation` is a host/human confirmation channel. Neither channel is exposed by MemoryTool or REST.
- Source and procedure must share a namespace. Deleted/cancelled sources are rejected. Source content/status changes invalidate associated traces; source deletion removes traces. Retrieval computes current status from remaining trusted traces, so a stale stored status cannot cause retrieval after its evidence disappears.
- Explicit `retrieve_procedures` returns confirmed workflows and failed-workflow warnings with source trace IDs. Exact declared environment constraints and required tool availability must match. Unverified procedures are excluded. No stored steps are executed, evaluated as Python, or automatically injected into model prompts. Prerequisites are returned for the host to check; they are not automatically inferred.
- Runtime commands: `timeline`, `explain`, `stats`, `export_memory`, `import_memory`, `delete_namespace`; session deletion is available through `runtime.advanced.delete_session`. These use the same SQLite source of truth. Stats count rows without materializing their contents.
- MemoryTool now uses Runtime rather than legacy ML memory. It exposes scoped remember/recall/procedures/forget/timeline/sleep through explicit invoke/ainvoke dispatch. It cannot confirm outcomes or choose another namespace in its action arguments.
- Optional LangChain history persists text human/AI/system messages with real roles and scoped session IDs. Clear deletes that session atomically, including beyond the displayed history cap; other sessions/namespaces remain. `wrap_runnable` delegates to the shared wrapper for text Runnables. Sync/async calls observe inputs, retrieve prior evidence, call the model once, store completions/failures. Async cancellation now stores a cancelled completion and propagates cancellation; async-only ainvoke models are supported.
- Optional REST is a factory with no module-level runtime/database/server creation. Host-configured bearer secrets map to fixed namespaces. Routes: public health, authenticated observe/search/timeline. Observations accept only content, bounded to 64 KiB; query length is capped. Scope override parameters are rejected. No outcome confirmation, executable enrichment, backup import or administrative deletion route is exposed.

## Public examples

```python
import nsn
rt = nsn.init('./agent-memory')
model = nsn.wrap(your_model)

procedure_id = rt.record_procedure(
    title='Count JSON items',
    steps=['Read UTF-8 file', 'Decode JSON', 'Count items'],
    prerequisites=['Readable input file'],
    environment={'format': 'json'}, tools=['file.read', 'json.decode'])
# Only trusted application code after checking the actual tool result:
trace_id = rt.append_event(role='tool', content='Count returned 3, expected 3')
rt.record_outcome(procedure_id=procedure_id, event_id=trace_id,
                  outcome='success', evidence='observed')
procedures = rt.retrieve_procedures('Count JSON items',
    environment={'format': 'json'}, tools=['file.read', 'json.decode'])
backup = rt.export_memory(namespace='default')
# On a separate runtime with an EMPTY destination namespace:
# destination.import_memory(backup, namespace='default')
```

The sample trace is illustrative: the host must check an actual result before recording observed success. The deterministic task runner performs real file reads/JSON decoding before recording outcomes.

## Backup and deletion contracts

Format `nsn-scoped-backup`, schema_version 7, exact namespace, exact table/column schemas. Export is a consistent read transaction. Import is a single writer transaction into an empty namespace; duplicate global IDs, existing namespace records/vectors, unknown schema versions, invalid scopes/references and missing columns are rejected without partial writes. Same-schema round trip preserves roles, event times, fact validity intervals, versions/revisions, sessions, source traces and derived lineage.

Backups include core events/facts/support, relationship tables, jobs, consolidation ledgers, derived support/cleanup, proposals, importance and procedures/traces. They exclude regenerable vectors/global encoder manifests, legacy Memory tables and global index checkpoints. Restore into a semantic runtime requires explicit `rebuild_vectors(namespace=...)`. Live processing job leases become pending on import; other persisted values are preserved. Source ledger revisions are restored after insertion-trigger work. FTS is reconstructed in the same transaction.

Backups are trusted operator artifacts, not arbitrary agent documents: they can include pending consolidation job settings (including a configured enrichment command). Import does not run jobs; a subsequent explicit sleep may resume such commands. Do not expose import to model-controlled inputs. Max supported backup size is 32 MiB; larger stores need a future streaming format. No namespace remapping, merge or older-schema conversion is supported yet. JSON export includes personal data; host controls its storage/access.

Namespace deletion removes core scoped records and vectors plus scoped legacy memories/graph rows. It leaves the shared encoder manifest and other namespaces intact. A regression warms a separate runtime's vector cache, deletes a namespace and verifies no stale results survive. FTS and derived data are removed. Session deletion invalidates dependent provenance but does not delete independent facts.

## Task evidence and research grounding

`benchmarks/run_procedure_tasks.py` performs a real training file task, retrieves its observed procedure, then explicitly runs a fixed host driver on three further files. Array count and empty-list count succeed; invalid JSON fails and its failure warning remains retrievable. Results: 2/3 successes, 3/3 procedure retrieval, zero model calls. This is an integration fixture, not an LLM improvement result or a procedure-execution engine. There is no comparative baseline or causal learning claim; Phase 09 must evaluate actual model decisions and task outcomes.

Feedback-backed episodic procedure reuse is inspired by [Reflexion (Shinn et al., NeurIPS 2023)](https://arxiv.org/abs/2303.11366), which studies language feedback stored for subsequent trials. NSN deliberately distinguishes trusted observed results from generated success claims. This implementation is not a reproduction of that paper's agents or reported benchmark gains.

## Limits and next phase

- Procedures are explicit small-store lexical retrieval, not learned policy weights, automatic semantic procedure extraction or automatic execution. Prerequisites remain host responsibilities. No general frontier-intelligence or competitor superiority claim.
- LangChain support is text Runnables and text human/AI/system history; structured multimodal/tool-call messages need a dedicated future adapter. History displays at most 10,000 oldest scoped messages; clear deletes all in that session.
- REST example binds `127.0.0.1`; operator owns token provisioning, trusted process/filesystem and TLS proxy for remote use. API deliberately has a small surface. No role hierarchy, distributed quotas or production multi-host service claim.
- Old integration constructors/legacy REST routes have changed: use runtime/data_dir, not db_path/legacy ML Memory. No implicit `api:app`; use create_app or the example. Base SDK remains compatible.
- Backups support only schema 7 and empty destinations, with explicit vector rebuilding. Pending-job import and host confirmation are trusted operations.
- Optional environments and built wheel remain local. Existing user changes were preserved; no commit, deployment or server startup.

Next: read `docs/implementation/09-real-evaluation.md` and the Phase 09 handoff for the partially implemented real-model/public-dataset/competitor gate. Do not equate the deterministic fixture with SLM quality.

## Follow-up prerequisite repairs

Procedure constraints now reject invalid container types: prerequisites/tools must be lists and environment must be a dictionary. Empty wrong-type values cannot bypass validation. A trusted `observed` success also requires a completed source event; a failed tool trace cannot confirm successful execution. `test_procedure_constraints_and_failed_source_cannot_confirm_success` covers these cases.
