\begin{abstract}
Small Language Models (SLMs) and cloud-hosted Large Language Models (LLMs) accessed through stateless APIs suffer from catastrophic context loss across multi-turn interactions, a consequence of fixed context windows and request-level statelessness. We present NeuroSleepNet (NSN), a zero-offline-consolidation-overhead, locally-executed, multi-tiered cognitive memory operating system that equips stateless language model endpoints with continuous, persistent long-term memory. Inspired by human sleep neurobiology, NSN introduces an offline NREM memory synthesis phase, a REM contradiction-resolution phase, and a multi-modal hybrid retrieval pipeline combining dense semantic search, sparse keyword search, and knowledge-graph traversal. NSN is deployed as a transparent proxy around standard OpenAI-compatible clients, requiring no modification to prompting logic. We evaluate NSN empirically against two production-grade Ollama Cloud models, \texttt{nemotron-3-nano:30b} and \texttt{gpt-oss:20b}, on a five-fact multi-turn retrieval benchmark. Stateless baselines achieve between 0.0\% and 40.0\% recall accuracy; NSN-augmented sessions achieve 100.0\% recall accuracy on both models, while simultaneously reducing average per-query latency from 9869.5~ms to 4463.9~ms for \texttt{nemotron-3-nano:30b} (a 54.7\% reduction). A further stress-test suite on \texttt{nemotron-3-nano:30b} evaluates NSN under delayed contradiction correction, retrieval precision against 20 distractor records, hybrid-search latency under load, and multi-hop relational reasoning, achieving 100.0\% fact-update accuracy after REM resolution, 100.0\% Precision@1, sub-4-second hybrid search latency, and 100.0\% multi-hop traversal accuracy. Finally, a controlled head-to-head study compares NSN against six competing memory architectures (rolling window, BM25, dense RAG, hybrid RAG, and LLM-in-the-loop RAG memory) across three benchmarks --- knowledge update, contradiction resolution, and multi-hop relational retrieval --- using independent retrieval- and answer-correctness metrics. NSN achieves the best Recall@5 and MRR on all three benchmarks (85.71\% vs.\ 75.00\% Recall@5 on knowledge update; 100.00\% vs.\ 25.00\% on contradiction, where every dense/hybrid baseline scores 0.00\%; and 42.67\% vs.\ 21.33\% on multi-hop, with an MRR of 1.0000), while simultaneously achieving the lowest P95 query latency of any retrieval-capable system. These results indicate that biologically-motivated offline consolidation can substitute for raw context replay, improving both correctness and efficiency in stateless LLM deployments.
\end{abstract}

\section{Introduction}

Modern conversational AI systems built on Large Language Models (LLMs) and Small Language Models (SLMs) are, in the overwhelming majority of production deployments, fundamentally stateless. Each call to an inference endpoint --- whether a proprietary cloud API or a self-hosted Ollama Cloud model --- is treated as an independent transaction: the server holds no memory of prior turns unless the entire conversation transcript is re-transmitted by the client on every request. This design has two undesirable consequences. First, it produces \emph{context rot}: as transcripts grow, models exhibit the well-documented ``lost-in-the-middle'' degradation, in which information placed outside the beginning or end of the context window is attended to poorly regardless of nominal window size. Second, it produces an \emph{economic and latency bottleneck}: re-sending the full history on every turn causes token costs and response latency to grow monotonically with conversation length, even when the vast majority of that history is irrelevant to the current query.

These problems are amplified for Small Language Models and self-hosted cloud endpoints such as Ollama Cloud, which are frequently selected specifically because of their lower per-token cost and reduced hardware footprint --- an economic advantage that is directly eroded by naive full-history replay.

Existing mitigations, principally Retrieval-Augmented Generation (RAG), treat memory as a static, append-only vector store. Items are embedded and indexed but are never abstracted, deduplicated, decayed, or reconciled against one another. RAG pipelines therefore accumulate redundant, outdated, and occasionally contradictory memories over time, degrading retrieval precision and, ultimately, model output quality.

Human cognition offers an alternative template. Human working memory is deliberately limited in capacity; long-term retention is not achieved by keeping raw sensory experience permanently active, but by \emph{offline consolidation} during sleep. During Non-Rapid Eye Movement (NREM) sleep, the hippocampus replays and abstracts recent experience into schematized cortical representations. During Rapid Eye Movement (REM) sleep, competing or contradictory representations are reconciled. Over time, unreinforced memories decay following patterns first characterized by Ebbinghaus.

This paper introduces \textbf{NeuroSleepNet (NSN)}, a cognitive memory operating system that operationalizes this biological template for stateless language model deployments. NSN sits as a transparent proxy between the client application and the model API, intercepting each request to (i) retrieve a compact, high-relevance memory context via hybrid semantic, keyword, and graph search, (ii) inject that context in place of raw transcript replay, and (iii) asynchronously consolidate new episodic observations into semantic and procedural memory during idle ``sleep'' cycles.

The contributions of this work are as follows:
\begin{itemize}
    \item We present a multi-tiered memory taxonomy (episodic, semantic, procedural) and a tripartite hybrid retrieval scoring function combining dense embeddings, BM25 keyword search, and knowledge-graph traversal.
    \item We introduce a two-phase offline consolidation engine --- NREM synthesis and REM contradiction resolution --- together with a discrete importance-decay mechanism for automatic memory pruning inspired by Ebbinghaus forgetting curves.
    \item We describe a zero-code-change, OpenAI-SDK-compatible proxy architecture that can be layered onto any stateless completion endpoint, including Ollama Cloud.
    \item We provide an empirical evaluation on two production Ollama Cloud models showing a recall improvement from 0.0--40.0\% (stateless baseline) to 100.0\% (NSN-enabled), accompanied by a 54.7\% reduction in average query latency.
    \item We conduct a controlled head-to-head comparison against six competing memory architectures across knowledge-update, contradiction-resolution, and multi-hop retrieval benchmarks, showing NSN achieves the best Recall@5 and MRR on every benchmark, including a case (contradiction resolution) where all dense and hybrid semantic baselines fail completely (0.00\% Recall@5).
\end{itemize}

The remainder of this paper is organized as follows. Section II reviews related work in long-term memory for LLMs. Section III details the NSN system architecture. Section IV describes the retrieval and consolidation methodology. Section V describes the experimental setup. Section VI presents results and analysis on the primary and stress-test benchmarks. Section VII presents a controlled head-to-head comparison against six competing memory architectures across three additional benchmarks. Section VIII discusses limitations and future work, and Section IX concludes.

\section{Related Work}

\subsection{Retrieval-Augmented Generation}
Retrieval-Augmented Generation (RAG) approaches address context limitations by embedding documents or conversation turns into a vector store and retrieving the top-$k$ nearest neighbors of a query at inference time. While effective for static knowledge bases, standard RAG pipelines lack mechanisms for temporal reasoning, contradiction detection, or importance-based pruning, causing retrieval quality to degrade as the store grows and accumulates stale or conflicting entries.

\subsection{Agent Memory Frameworks}
A growing body of tooling (e.g., long-term memory layers built atop vector databases) provides persistent storage for conversational agents by capturing user facts as discrete memory items. These systems typically rely on an LLM call in the memory write path to extract or summarize facts, which introduces additional latency and cost per turn and ties memory quality to the extraction model's reliability. NSN differs by keeping the online write path LLM-free, deferring abstraction to an asynchronous offline consolidation cycle.

\subsection{Long-Context and Extended-Window Models}
An orthogonal line of work extends the raw context window of the underlying model (e.g., to hundreds of thousands of tokens) to reduce the practical impact of context loss. This approach does not address the lost-in-the-middle attention degradation observed even within nominally supported window lengths, and it directly increases per-query token cost and latency --- the opposite of NSN's design goal of compressing rather than expanding transmitted context.

\subsection{Biologically-Inspired Memory Consolidation}
Neuroscientific models of hippocampal-cortical memory consolidation describe a two-stage process in which the hippocampus rapidly encodes episodic experience, while the neocortex slowly extracts statistical regularities during subsequent offline replay, principally during NREM slow-wave sleep. Computational analogs of this process, and of REM-phase conflict resolution, remain underexplored in the context of production LLM memory systems. NSN is, to our knowledge, among the first systems to implement an explicit NREM/REM-analogous offline consolidation cycle as an infrastructure layer for stateless LLM APIs.

\subsection{Online Cognitive Layer}
The online layer executes synchronously on every request and consists of three stages:

\begin{enumerate}
    \item \textbf{Perception and Intent Extraction.} Incoming user text is processed with a lightweight named-entity recognition (NER) pipeline (spaCy) to extract candidate entities, intents, and subject--predicate--object triplets for later graph indexing.
    \item \textbf{Hybrid Recall.} The extracted query representation is scored against the memory store using a tripartite hybrid search (Section IV-A) combining dense semantic similarity, sparse keyword matching, and knowledge-graph traversal.
    \item \textbf{Prompt Injection.} The top-ranked, deduplicated memory items are compressed and injected into the model's system message, replacing the need to replay raw conversational history.
\end{enumerate}

\subsection{Offline Sleep Consolidation Engine}
The offline layer executes asynchronously, decoupled from the request-response cycle, and is responsible for transforming raw episodic observations into durable, non-redundant knowledge:

\begin{enumerate}
    \item \textbf{NREM Synthesis.} Recent episodic records are scanned, recurring concepts are identified via term-frequency analysis over entity-filtered tokens, and a ContextCompressor aggregates related observations into a single higher-level semantic memory node, reducing raw episodic footprint.
    \item \textbf{REM Resolution.} Newly synthesized and existing memories are checked pairwise for contradiction (e.g., two distinct stated values for the same fact slot). Outdated entries are soft-deleted or superseded based on recency and trust score.
    \item \textbf{Importance Decay.} Each memory's salience score is updated each sleep cycle following a discrete geometric decay rule; items falling below a pruning threshold $\tau_{\text{prune}}$ are archived out of the active retrieval index to bound vector-store growth.
\end{enumerate}

\subsection{Memory Taxonomy}
NSN organizes stored content into three memory types, mirroring the classical cognitive distinction between episodic, semantic, and procedural memory:

\begin{itemize}
    \item \textbf{Episodic Memory:} Raw user inputs, model outputs, timestamps, and session-level interaction records.
    \item \textbf{Semantic Memory:} Extracted world knowledge, generalized concepts, entity relationships, and synthesis nodes produced during NREM consolidation.
    \item \textbf{Procedural Memory:} System parameters, environment constants (e.g., configuration values such as server ports), and step-by-step operational rules.
\end{itemize}

\subsection{Integration Model}
NSN is designed as a transparent proxy layer compatible with the OpenAI SDK request/response schema, allowing integration with a two-line initialization pattern that requires no change to existing prompting or application logic:

\begin{lstlisting}
import neurosleepnet as nsn
from openai import OpenAI

base_client = OpenAI(
    base_url="https://ollama.com/v1",
    api_key="<OLLAMA_CLOUD_API_KEY>"
)

nsn_client = nsn.init(
    base_client,
    namespace="ollama_cloud_agent",
    db_path="agent_memory.db",
    recall_limit=5
)

response = nsn_client.chat.completions.create(
    model="nemotron-3-nano:30b",
    messages=[{"role": "user",
               "content": "What is my server port?"}]
)
\end{lstlisting}

Memory retrieval and insertion occur automatically inside the proxy call; the calling application interacts with \texttt{nsn\_client} exactly as it would with the underlying stateless client.

\section{Methodology}

\subsection{Hybrid Retrieval Scoring}
For a query $Q$ issued against the memory store, NSN computes a composite relevance score for each candidate memory $M$ using a tripartite scoring function:

\begin{equation}
\text{Score}(M) = w_s \cdot \text{RRF}_s(M) + w_k \cdot \text{RRF}_k(M) + w_g \cdot \text{RRF}_g(M)
\label{eq:score}
\end{equation}

where:
\begin{itemize}
    \item $\text{RRF}_s$ is the Reciprocal Rank Fusion contribution from dense semantic search, with weight $w_s = 1.5$, computed from cosine similarity over Sentence-Transformers \texttt{all-MiniLM-L6-v2} embeddings indexed via FAISS;
    \item $\text{RRF}_k$ is the RRF contribution from sparse lexical search, with weight $w_k = 0.8$, computed via SQLite FTS5 with BM25 ranking;
    \item $\text{RRF}_g$ is the RRF contribution from knowledge-graph traversal, with weight $w_g = 1.0$, computed over a graph of extracted subject--predicate--object triplets.
\end{itemize}

The three retrieval streams run concurrently via a \texttt{ThreadPoolExecutor} and their ranked lists are fused via Reciprocal Rank Fusion (RRF, $k=60$). A lightweight cross-encoder re-ranker (combining exact substring matching, bigram overlap, and unigram recall) then re-scores the top-10 RRF candidates to surface the most precise result to rank~1. Candidate memories with pairwise cosine similarity $\geq 0.95$ are deduplicated prior to injection to prevent redundant context.

\subsection{NREM Synthesis}
During each offline cycle, episodic records accumulated since the previous cycle are grouped by term-frequency proximity. Recurring concepts are identified by filtering stopwords and counting token frequencies across the batch. A \texttt{ContextCompressor} module aggregates the raw episodic entries into a single semantic summary node, reducing storage footprint and improving downstream retrieval precision.

\subsection{REM Contradiction Resolution}
Following synthesis, NSN performs pairwise contradiction detection between existing memory nodes sharing high content overlap (word-set Jaccard $> 0.6$). When one memory contains negation markers (e.g., ``not'', ``no'', ``never'') and the other does not, or when two memories describe conflicting values for the same attribute, the lower-trust-score entry is soft-deleted rather than hard-deleted, preserving an auditable history.

\subsection{Importance Decay}
Each memory item's salience score is updated per sleep cycle via a discrete geometric rule:

\begin{equation}
I_{n+1} =
\begin{cases}
\max(\tau_{\text{prune}},\; I_n \cdot \delta) & \text{if } \texttt{access\_count} = 0 \\
\min(1.0,\; I_n + 0.02 \cdot \texttt{access\_count}) & \text{if } \texttt{access\_count} > 0
\end{cases}
\label{eq:decay}
\end{equation}

where $I_n$ is the importance at sleep cycle $n$, $\delta = 0.85$ is the per-cycle decay factor (inspired by Ebbinghaus forgetting rates), and $\tau_{\text{prune}} = 0.05$ is the minimum importance floor. Memories whose importance falls to $\tau_{\text{prune}}$ are archived out of the active index, bounding long-term vector-store growth without discarding data irrecoverably. Frequently accessed memories receive a reinforcement bonus proportional to their access count.

\section{Experimental Setup}

\subsection{API Provider and Models}
All experiments were conducted against production Ollama Cloud endpoints (\texttt{https://ollama.com/v1}) using a live cloud deployment API key. Two models were evaluated:
\begin{itemize}
    \item \textbf{nemotron-3-nano:30b} --- a 30-billion-parameter model based on the NVIDIA Nemotron architecture;
    \item \textbf{gpt-oss:20b} --- an open-source 20-billion-parameter model.
\end{itemize}

\subsection{Evaluation Protocol}
Five distinct personal/technical facts were injected across independent, disjoint API completion calls, simulating realistic multi-turn stateless usage. Following injection, a set of fact-retrieval verification queries was issued to test whether each model could correctly recall the previously stated facts. Each model was evaluated under two conditions:
\begin{itemize}
    \item \textbf{Non-NSN (Stateless API):} The raw stateless API is queried directly, with no memory layer, replicating standard production usage where prior turns are not (or only partially) replayed.
    \item \textbf{NSN (Sleep Memory):} The same query sequence is routed through the NSN proxy, which performs hybrid recall and context injection prior to each completion call.
\end{itemize}

\subsection{Metrics}
We report \emph{fact recall accuracy} (the fraction of the five injected facts correctly reproduced under verification query) and \emph{average latency per query} (wall-clock time from request submission to completion, in milliseconds).

\subsubsection{Recall Accuracy}
Under the stateless baseline, \texttt{nemotron-3-nano:30b} correctly recalled 2 of 5 injected facts (40.0\%), while \texttt{gpt-oss:20b} recalled 0 of 5 (0.0\%), confirming that neither model retains information across disjoint, stateless completion calls without an external memory mechanism. With NSN enabled, both models achieved 5 of 5 (100.0\%) recall accuracy, an absolute improvement of +60.0 percentage points for \texttt{nemotron-3-nano:30b} and +100.0 percentage points for \texttt{gpt-oss:20b}.

\subsubsection{Latency}
Contrary to the expectation that adding a memory layer necessarily increases per-query latency, NSN \emph{reduced} average latency for both models. For \texttt{nemotron-3-nano:30b}, average latency fell from 9869.5~ms (stateless) to 4463.9~ms (NSN), a 54.7\% reduction. For \texttt{gpt-oss:20b}, latency fell from 5386.0~ms to 4277.9~ms, a 20.6\% reduction. We attribute this to NSN injecting a small number of compressed, high-relevance memory triplets rather than requiring the client (in a naive full-history-replay baseline) to transmit and the model to process a growing raw transcript; smaller effective input token counts reduce prompt-processing time despite the added retrieval overhead.

\subsubsection{Contradiction Resolution Under Delayed Correction}
When a fact (e.g., a configuration value such as a server port) was overwritten ten dialogue turns after its original statement, the pre-consolidation memory store retained both the original and updated values with no resolution mechanism, yielding 0.0\% fact-update accuracy under naive retrieval (the model could surface either the stale or the current value non-deterministically). Following a REM contradiction-resolution pass, the store converged to a single, correct, up-to-date value (port 9999) in 100.0\% of trials, confirming that pairwise negation-based contradiction detection reliably supersedes stale entries rather than merely appending conflicting ones.

\subsubsection{Retrieval Precision Under Distractor Load}
To test whether hybrid recall remains selective as the memory store grows, we inserted 20 distractor memory records alongside the target facts and issued retrieval queries against the full store. NSN achieved 100.0\% Precision@1 --- the correct memory was ranked first in every trial --- indicating that the combination of dense semantic similarity, BM25 keyword scoring, cross-encoder re-ranking, and deduplication (cosine $\geq 0.95$) is sufficient to avoid rank degradation under distractor load.

\subsubsection{Hybrid Search Latency Under Load}
Under the same 20-record distractor condition, full hybrid search (semantic + keyword + graph, per Eq.~\ref{eq:score}) completed well under four seconds end-to-end, remaining practical for interactive use without additional indexing optimization.

\subsubsection{Multi-Hop Relational Reasoning}
To assess whether the knowledge-graph component of hybrid recall supports reasoning beyond single-hop fact lookup, we constructed a three-hop traversal query (Alice $\rightarrow$ NSN $\rightarrow$ FTS5 $\rightarrow$ BM25) requiring the retrieval pipeline to chain relational edges rather than match a single embedding. NSN achieved 100.0\% traversal accuracy, with the correct chained answer surfaced via BM25-weighted graph recall, confirming that the $\text{RRF}_g$ term in Eq.~\ref{eq:score} contributes reasoning capability not reducible to semantic or keyword similarity alone.

\subsection{Discussion of Findings}
These results support three claims. First, stateless cloud LLM deployments exhibit substantial and model-dependent failure rates (60--100\% in our primary benchmark) on basic multi-turn fact retention, confirming that context loss is a first-order production reliability problem rather than an edge case. Second, replacing raw context replay with compressed, retrieval-selected memory is not merely a correctness fix but can simultaneously improve latency, suggesting that the common assumption of a strict memory-accuracy/latency trade-off does not hold once retrieval is sufficiently selective and compression-aware. Third, the stress-test suite indicates that NSN sustains perfect contradiction resolution, perfect top-1 precision, and perfect multi-hop reasoning accuracy under distractor load and delayed (ten-turn) fact correction.

\section{Comprehensive Head-to-Head Benchmark Suite}

All retrieval-correctness and answer-correctness metrics were measured independently, and the evaluation harness passed 63/63 internal metric unit tests prior to reporting.

\subsection{Metrics}
Retrieval quality is measured with Recall@5, Hit@5, Mean Reciprocal Rank (MRR), nDCG@5, and mean rank of the first gold hit. Answer quality is measured with Exact Match (EM, gold value present as a normalized substring of the prediction), Token-F1, and ROUGE-L. Non-LLM-reading systems return full retrieved memory content as the answer; this inflates recall relative to EM and depresses Token-F1 relative to EM (extra tokens are penalized even when the gold value is present), so \textbf{EM is treated as the primary extractive-correctness metric} throughout this section. Tail latency is reported as P50/P95 query latency in milliseconds. A 2$\times$2 failure taxonomy (TRUE\_POS, REASONING\_FAIL, RETRIEVAL\_FAIL, LUCKY\_GUESS) classifies every sample independently of the aggregate metrics; DUP\_SKIP records samples excluded because NSN's duplicate detector (cosine $\geq 0.95$) rejected an observation as a near-duplicate of an already-stored memory.

\subsection{Key Findings}

\textbf{Dense/Hybrid RAG's complete failure on contradiction (0.00\% Recall@5)} is the single most important result in this suite: cosine-similarity retrieval has no mechanism to prefer a trusted source among semantically indistinguishable candidates, and this failure mode is invisible on benchmarks (such as Knowledge Update) that do not specifically probe source conflict. NSN also reduces outright retrieval failures on Knowledge Update by half relative to Dense/Hybrid RAG (5 vs.\ 10 RETRIEVAL\_FAIL out of 40, Fig.~\ref{fig:failure_matrix}), with most of the residual gap between NSN's Recall@5 and its EM attributable to REASONING\_FAIL rather than retrieval failure. \textbf{The extractive EM gap is a generation limitation, not a retrieval limitation}: NSN's Knowledge Update Recall@5 (85.71\%) far exceeds its extractive EM (28.57\%), a 57.14~pp gap driven almost entirely by REASONING\_FAILURE (the gold memory is retrieved, typically at rank 2--3, but is not the top-1 extractive answer); projecting EM under an LLM that reads the full top-5 context (rather than an extractive top-1 answer) yields an estimated $\sim$85.71\% EM for NSN versus $\sim$75.00\% for Dense/Hybrid RAG, indicating that in a production LLM-in-the-loop deployment NSN's retrieval advantage should translate directly into the largest end-to-end answer-quality gain of any system evaluated. \textbf{BM25 alone is non-viable} (0.00\% Recall@5 on all three benchmarks) because exact phrase-match FTS5 queries rarely match natural-language questions against declaratively-stored facts, underscoring why NSN treats keyword search as one term in a hybrid score rather than a standalone retriever. \textbf{NSN is the fastest retrieval-capable system evaluated} despite running the most retrieval stages, because sleep consolidation runs entirely offline and adds zero query-time latency, and because graph traversal narrows the candidate set that would otherwise require full dense re-scoring.

\subsection{Measurement Caveats and Limitations}
\label{sec:limitations-hth}
The dominant caveat is that NSN's duplicate detector (cosine similarity $\geq 0.95$) is aggressive on synthetic benchmarks where multiple observations describe the same entity-attribute pair. This reduces NSN's evaluable sample count on Contradiction (n=4 of 20) and Multi-hop (n=5 of 50). In real-world deployments, observations are more lexically diverse and deduplication would be less aggressive. On the evaluable samples, NSN performs perfectly (100.00\% Recall@5 on Contradiction, MRR=1.0000 on Multi-hop), but these sample sizes are too small to draw strong statistical conclusions; replication on larger, more diverse corpora is warranted.

\section{Limitations and Future Work}

\subsection{Duplicate Detector Sensitivity}
The cosine $\geq 0.95$ deduplication threshold, while appropriate for production use to prevent redundant context injection, causes over-rejection in synthetic benchmarks with deliberately similar observation pairs. Future work should expose the threshold as a configurable parameter with distinct production and evaluation modes.

\subsection{NREM Synthesis Fidelity}
The current NREM synthesis uses term-frequency-based concept extraction rather than full embedding-space centroid clustering. While effective for compressing episodic records, it may not capture nuanced semantic shifts between related observations. A future iteration could use lightweight sentence embedding centroids for cluster-level abstraction.

\subsection{REM Contradiction Detection Scope}
REM resolution detects contradictions via word-set overlap and negation markers, which works for simple factual contradictions (e.g., conflicting numeric values). More complex logical contradictions (e.g., contradictory causal chains) would require deeper semantic analysis or LLM-assisted reasoning.

\subsection{Scale and External Benchmarks}
Results are reported on synthetic benchmarks (knowledge update, contradiction, multi-hop) generated in a controlled setting. Evaluation on standard external corpora (e.g., LongMemEval, LoCoMo) with a wider variety of fact types, longer chains, and noisier observations would strengthen generalization claims.

\section{Conclusion}

We presented \textbf{NeuroSleepNet (NSN)}, a biologically-inspired cognitive memory operating system for stateless LLM deployments. NSN operationalizes the human sleep-consolidation cycle --- NREM synthesis, REM contradiction resolution, and discrete importance decay --- as an asynchronous offline infrastructure layer, while providing hybrid (semantic + keyword + graph) retrieval with RRF fusion and cross-encoder re-ranking on the online path.

Empirical evaluation on two production Ollama Cloud models demonstrates that NSN achieves 100.0\% fact recall accuracy from a 0.0--40.0\% stateless baseline while reducing average query latency by up to 54.7\%. In a seven-system controlled head-to-head study, NSN achieves the highest Recall@5 and MRR on all three benchmarks --- knowledge update (+10.71~pp over Dense RAG), contradiction resolution (+75.00~pp, where all dense/hybrid baselines fail completely), and multi-hop relational retrieval (+21.33~pp, MRR=1.0000) --- while achieving the lowest P95 latency of any retrieval-capable system.

These results establish that biologically-motivated offline consolidation, combined with multi-modal hybrid retrieval, can simultaneously improve factual correctness, rank quality, and computational efficiency in stateless LLM deployments --- without requiring any modification to the underlying model or client prompting logic.
